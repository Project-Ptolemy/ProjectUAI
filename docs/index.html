  • instance_cloneWrite

  • instance_destroyHigh impact

  • instance_edit_manyWrite

    Apply ordered typed property/attribute/tag operations with expected values or an observed snapshot. Preflight conflicts produce zero writes. Property/attribute changes share Game changes Undo.

  • instance_findRead

    Search a subtree for instances by name and/or class. Stops when the requested result count is reached. For selected properties and paginated results, use instance_query.

  • instance_getRead

    Read an instance's properties, attributes and tags. Do this before setting anything.

  • instance_get_manyRead

  • instance_parentWrite

    Reparent an instance.

  • instance_queryRead

    Find instances and read selected properties/attributes in one call. Name is a case-insensitive substring; class uses IsA. Stops as soon as a page fills, without collecting the entire subtree. Search is capped at 20,000 nodes.

  • instance_result_readRead

    Read bounded retained detail from a large result in this tool group. Follow returned path arrays and offsets; expires after five minutes.

  • instance_setWrite

    Set one property on one instance. The value is converted to the property's existing type, so 'Size' takes '4, 1, 2' on a part and '0, 200, 0, 40' on a GUI frame.

  • instance_taggedRead

    List instances carrying a CollectionService tag, or list every tag in use.

  • instance_treeRead

    Read a depth-limited tree within the result budget. Reports omitted/unreadable branches; use explorer_children for complete paginated children of a known handle.

  • check_luauRead

    Check Luau syntax without executing code or changing the game. Provide inline 'code' or a saved file 'path', not both. Prefer path for scripts you wrote or edited so their source need not be sent again. Returns compile errors for correction before run_luau.

    Requires exec
  • run_luauHigh impact

    Run bounded Luau on the local client. Provide inline source in 'code', or 'path' to run a workspace file directly without reading it back first. Captures print/warn, tables and all return values; waits for functions started with task.spawn/defer/delay. Stop or the deadline cancels managed tasks. Loop checkpoints yield automatically. Prefer a specific tool when one exists. This is not a security sandbox; dynamically loaded code and engine calls can bypass cooperative guards.

    Requires exec
  • script_listRead

    Find script instances by root, kind and optional name substring. Returns source references and a stable continuation cursor. Default 25, maximum 100 per page; bounded tree scans disclose incomplete coverage. Read only relevant sources.

  • script_result_readRead

    Read bounded retained detail from a large result in this tool group. Follow returned path arrays and offsets; expires after five minutes.

  • script_sourceRead

    Read a script's source. Works when the host can read or decompile it; when the host has no decompiler or it fails, the bundled luacid client and then the ByteFall service are tried. Many live scripts still cannot be read at all.

  • scripting_docsRead

    Read the offline guide to the live Roblox environment and script development. Start with quickstart; select environment/capabilities, native workflows, shared state/concurrency, executor APIs with sUNC references, paths, inspection, Luau, cleanup, UI, debugging, projects, editor or verification as needed. Reuse retained sections. No network, filesystem access or execution required.

Agent16 tools+
  • agent_followupWrite

    Continue a completed subagent with its existing context. Returns its id immediately by default; do independent work while it runs, check agent_status periodically and collect the new report. Use the id from dispatch_agent or agent_status. Set background=false only when this call must wait for the answer.

  • agent_statusRead

    Check subagents owned by this conversation. Omit id for compact statuses; give an exact id for current progress or its completed report. Reports and lists use bounded UTF-8 byte pages: follow nextOffset with offset until eof. Check after 2-3 work batches or about 15-30 seconds, while continuing independent work. When no independent work remains, wait_seconds=1-30 waits for a selected child to finish or the deadline; 0 returns immediately. Never tight-poll. Waiting does not stop the children.

  • ask_userRead

    Ask the user one question and wait for their answer. Use when a request is genuinely ambiguous -- two ways to read it, a choice of targets, a preference you cannot infer -- and answering it wrong would waste work. Offer concrete options when the plausible answers are few; omit them for an open question. The answer comes back as this call's result. You cannot ask from a subagent.

  • context_archiveRead

    Recover earlier messages that compaction removed from the live context. list shows archived segments; search finds literal text; read pages one segment by UTF-8 byte offset. Use this after a handover when you need exact earlier wording, paths, tool output or a decision that was folded away. It never changes the conversation or re-runs a tool.

  • conversation_listRead

    List this user's other conversations for review, most recent first, each with its id, title, place, age, size and opening request. Use it to triage which past thread is relevant, then read that one with conversation_read. Untouched empty chats are omitted; the current conversation is marked and does not need reading. Query filters on the title or the opening request.

  • conversation_readRead

    Read one of this user's other conversations by id (from conversation_list or conversation_search). Condensed by default: the whole thread with long turns shortened and tool runs collapsed, so a review costs one bounded read. Pass full=true for the verbatim transcript in UTF-8-safe byte slices, following nextOffset for the rest. Use it after a list or search points at a relevant thread, so you carry forward what was decided instead of re-deriving or re-asking it.

  • conversation_renameWrite

    Rename this conversation to a short, specific title based on what it is actually about, so the user can pick the thread out of their list later. Call it once the subject is clear -- usually after the first exchange -- and again only when the work has genuinely moved on. Name the job, not the tools used. Never use it to replace a name the user set themselves; a conversation the user has named is not offered this tool.

  • conversation_searchRead

    Search other conversations and saved pastes for prior work using a literal query. Returns exact conversation IDs or paste paths and snippets; read details with conversation_read or file_read. scope can restrict the search. Work is bounded and incomplete searches are disclosed; narrow follow-ups rather than assuming absence. The current conversation is excluded.

  • dispatch_agentWrite

    Start a self-contained task in a background subagent and immediately receive its id. Keep doing your own independent work while it runs; check agent_status periodically and collect its report before your final answer. Give each worker a distinct scope and avoid concurrent edits to the same file or runtime state. A subagent cannot ask questions, so include the full task and completion criteria. Set background=false only when this tool call must wait for the report.

  • memory_forgetWrite

    Delete one remembered key.

  • memory_readRead

    Read a saved memory by exact key, search keys/values with a literal query, or list all memories. Historical facts may be stale; current instructions and observed state take precedence. Follow returned offsets with the same filters.

  • memory_writeWrite

    Save a durable fact about this user or project under a short key. Survives context compaction and restarts. Use for preferences, paths and goals, not for transcript chatter.

  • todo_readRead

    Read the current task list.

  • todo_writeWrite

    Replace the full task list. Use when substantial work benefits from a tracked plan; keep one item active while work remains. Routine tool sequences need no list.

  • tool_searchRead

    Find tools hidden by the active tool profile. action=list returns names and one-line descriptions; action=describe returns a tool's exact schema pages; action=call runs that tool with its declared arguments. Hidden tools keep their normal permissions and conversation scope. Core tools are already declared; use this only when the needed tool is absent.

  • waitRead

    Pause for a few seconds before continuing, to let something in the game settle or a change take effect.

Infinite Yield10 tools+
  • iy_cmdWrite

    Run an Infinite Yield command by its command string, exactly as typed into IY's own bar: 'speed 100', 'noclip', 'tp PlayerName', 'esp players'. Supports IY's repeat prefixes ('5^speed 100', 'inf^0.5^esp'). When the setting is on but IY is not loaded, this call loads it.

  • iy_cmdsRead

    List Infinite Yield commands, optionally filtered by a keyword or limited to one plugin's commands. Shows names, aliases, plugin origin, and argument signatures and descriptions when IY exposes them. Use it before iy_cmd to check syntax.

  • iy_controlWrite

    Inspect and configure Infinite Yield's saved events, keybinds, aliases, waypoints and settings. Inspect first for current 1-based binding indexes, event fields and defaults. Supports OnExecute, OnSpawn, OnDied, OnDamage, OnKilled, OnJoin, OnLeave and OnChatted. Event commands can use $1/$2 arguments; native IY ignores commands containing 'plugin'. Edits refresh IY's editor and request its normal save. Waypoints default to the current place. Use iy_cmd to execute commands, iy_plugin_write for plugins/custom events. stop_loops sends breakloops.

  • iy_playersRead

    Resolve an IY selector to concrete names in the live server (read-only). Keywords: all, others, me, random, #<n>, %<team>, allies, enemies, team, nonteam, friends, nonfriends, guests, bacons, age<n>, nearest, farthest, group<id>, alive, dead, rad<n>, cursor, npcs. Supports + include/- exclude, comma-separated lists, and @name for username-only prefix matching. Uses the running IY's selector behavior; resolve targets before iy_cmd.

  • iy_plugin_installWrite

    Install a plugin from the Infinite Yield store: downloads its .iy file, saves it to the workspace and registers it with the running Infinite Yield, whose commands then work through iy_cmd. Accepts the plugin name ('dexrecontinued'), a filename ('dexrecontinued.iy') or the store id.

  • iy_plugin_readRead

    Read an authored .iy plugin from the executor workspace, or omit plugin to get a multi-command template. Follow nextOffset for long sources. Use this before updating a plugin with iy_plugin_write.

  • iy_plugin_searchRead

    Search the Infinite Yield community plugin store (iyplugins.pages.dev, several hundred plugins) by name, author or filename. Returns matches with their authors. Use it when the user asks for a feature core IY does not have, then install with iy_plugin_install.

    Requires http
  • iy_plugin_uninstallWrite

    Remove a plugin: unregisters its commands from Infinite Yield and deletes its .iy file. Accepts the name with or without the .iy ending.

  • iy_plugin_writeHigh impact

    Create or update a custom Infinite Yield .iy plugin. Get the template with iy_plugin_read. Source may declare shared locals/globals above local Plugin, and must return a table with PluginName, PluginDescription and Commands. Each command has ListName, Description, Aliases and Function(args, speaker). Prefer a saved path for long source. Checks syntax before saving. By default executes setup once, validates the returned table and loads/reloads it through IY, returning actual registered command names. load=false only saves syntax-checked source. Set overwrite=true to replace an existing file. Reloading replaces commands; plugin-owned event connections or loops need cleanup in the plugin's own setup/unload command.

    Requires fs, exec
  • iy_statusRead

    Report Infinite Yield: the Settings mode, whether it is loaded, how it was obtained (already running, or loaded by this client), the command count and prefix. This inspection does not load IY; command tools ensure availability themselves.

A FEW GOOD QUESTIONS

Before
you begin.

Does every tool work in every executor?+

UAI detects the host’s capabilities. File access, code execution, virtual input, and other tools depend on the functions your host provides. Tools that need missing capabilities are omitted from the model’s available tools.

Which models can I use?+

Models that support tool calls through compatible Chat Completions or Anthropic Messages endpoints. Hosted providers, relays, Ollama, LM Studio, and vLLM can work when they expose a compatible endpoint. Fetch the model list or enter a model by hand.

What happens when I press Stop?+

Stop cancels the current agent turn and managed Luau tasks cooperatively. Execution has a default 10-second deadline, adjustable up to 60 seconds. Native engine calls, dynamically loaded code, and persistent event callbacks can fall outside that cancellation. Changes that already happened are not rolled back.

Where do my data and requests go?+

Settings, conversations, and activity are stored in your executor’s workspace when filesystem support is available. Your inference provider receives the context and tool results used to answer a request. Provider keys belong in UAI’s settings.

Is Project UAI free?+

Project UAI is open source under the MIT license. Project UAI Free is an optional provider in the Providers library, separate from HCNSEC. It is not added automatically; shared capacity and speed vary. Other model providers set their own pricing and availability.

Can I connect an Obsidian vault?+

Connect the desktop bridge, configure a local vault, and use the Obsidian tools to search and work with notes. Only configured vaults are available; edits check the note revision before writing. Read the vault setup guide.

What if I already have UAI running?+

Loading the same build requests the existing interface after any required vault unlock. A newer build uses the guarded save-and-reload flow. Cowork, UI LIB, and the embedding SDK provide other ways to work with the same project.
